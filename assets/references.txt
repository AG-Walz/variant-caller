# Reference files for scripts/setup.py — edit freely, this is data, not code.
#
# One file per line, tab-separated: the URL to fetch, where to put it relative to the
# destination directory you pass to setup.py, and optionally its md5. Blank lines and
# #-comments are ignored. Anything aria2c can fetch works, so a local mirror or an internal
# http server is a drop-in replacement — and the third column is optional, so a mirror that
# publishes no digest still works.
#
# The digests below are the ones Google Cloud Storage publishes for these objects, harvested
# with `curl -sI <url>` and read out of the `x-goog-hash: md5=` header (base64, so pipe it
# through `base64 -d | xxd -p`). They matter because aria2c's --continue treats a file of the
# right SIZE as finished: a reference corrupted in place is never re-fetched, and every run
# afterwards is quietly wrong. With a digest, aria2c re-downloads it instead.
#
# These are the GATK GRCh38 bundle and GATK's somatic best-practice resources. They are the
# build the pipeline is validated against: swapping in a different genome build means the
# target BED, the germline resource and the vendor's own calls all have to move with it.

# Upstream these are named .fasta.64.* ("64" is bwa's 64-bit index format), but bwa finds
# its index by looking for the .amb/.ann/... siblings of a common prefix, so they are
# renamed on arrival to match the FASTA's basename. Point the params file's `bwa:` at the
# bwa/ directory these land in.
#

# 402,168,392 against 1,608,673,512. Dropping `.64.` silently gives you a different index.
